## 🎯 v1.5.0 核心功能：账单数据持久化

### 当前问题

- 账单数据存储在 localStorage，容量有限（5-10MB）
- 数据易丢失，浏览器清理缓存会导致数据丢失
- 无法支持大量历史数据
- 跨设备访问困难

## 📊 数据库表设计

### 1. bill_import - 账单导入记录表

记录每次导入操作的元信息

```sql
CREATE TABLE bill_import (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    import_name VARCHAR(200) NOT NULL COMMENT '导入批次名称',
    source_file VARCHAR(200) COMMENT '源文件名',
    file_type VARCHAR(20) COMMENT '文件类型：CSV/EXCEL',
    import_time DATETIME COMMENT '导入时间',
    record_count INTEGER COMMENT '记录数量',
    new_count INTEGER COMMENT '新增记录数',
    update_count INTEGER COMMENT '更新记录数',
    duplicate_count INTEGER COMMENT '重复记录数',
    account_number VARCHAR(50) COMMENT '账户号码',
    period_start DATE COMMENT '账单起始日期',
    period_end DATE COMMENT '账单结束日期',
    import_status VARCHAR(20) DEFAULT 'SUCCESS' COMMENT '导入状态：SUCCESS/FAILED/PARTIAL',
    error_message TEXT COMMENT '错误信息',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 2. bill_transaction - 账单交易明细表

存储去重后的唯一交易记录

```sql
CREATE TABLE bill_transaction (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    transaction_date DATE NOT NULL COMMENT '交易日期',
    transaction_time TIME COMMENT '交易时间',
    income DECIMAL(15,2) COMMENT '收入金额',
    expense DECIMAL(15,2) COMMENT '支出金额',
    balance DECIMAL(15,2) COMMENT '账户余额',
    transaction_type VARCHAR(100) COMMENT '交易类型',
    description TEXT COMMENT '交易描述',
    payment_channel VARCHAR(50) COMMENT '支付渠道',
    category VARCHAR(50) COMMENT '交易分类',
    user_note TEXT COMMENT '用户备注',
    exclude_from_stats BOOLEAN DEFAULT 0 COMMENT '是否排除统计(0-计入 1-排除)',
    first_import_id INTEGER COMMENT '首次导入记录ID',
    last_import_id INTEGER COMMENT '最后更新导入ID',
    import_count INTEGER DEFAULT 1 COMMENT '导入次数',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 3. bill_transaction_import - 交易导入关联表

记录交易与导入的多对多关系

```sql
CREATE TABLE bill_transaction_import (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    transaction_id INTEGER NOT NULL,
    import_id INTEGER NOT NULL,
    is_new BOOLEAN DEFAULT 1 COMMENT '是否为新增(1-新增 0-重复)',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (transaction_id) REFERENCES bill_transaction(id),
    FOREIGN KEY (import_id) REFERENCES bill_import(id),
    UNIQUE(transaction_id, import_id)
);
```

### 4. 索引创建

```sql
CREATE INDEX idx_bill_transaction_date ON bill_transaction(transaction_date);
CREATE INDEX idx_bill_transaction_category ON bill_transaction(category);
CREATE INDEX idx_bill_transaction_first_import ON bill_transaction(first_import_id);
CREATE INDEX idx_transaction_import_transaction ON bill_transaction_import(transaction_id);
CREATE INDEX idx_transaction_import_import ON bill_transaction_import(import_id);
```

## 🔄 重复导入处理策略

### 当检测到重复交易时：

#### 1. bill_transaction 表处理

- **保持原有交易数据**（不覆盖）
- **更新追踪字段**：
  * `last_import_id` = 当前导入ID
  * `import_count` += 1
  * `update_time` = 当前时间
- **保护用户修改**：
  * `user_note` 不更新（保留用户备注）
  * `category` 不更新（保留用户分类）
  * `exclude_from_stats` 不更新（保留用户设置）
- **可选更新字段**：
  * `balance` 可更新（使用最新余额）

#### 2. bill_transaction_import 关联表

- 新增一条关联记录
- `is_new` = 0 （标记为重复）

#### 3. bill_import 统计

- `duplicate_count` += 1

### 示例场景

```
第一次导入（import_id=1）：
  bill_transaction:
    id=100, description="午餐", expense=50.00, 
    first_import_id=1, last_import_id=1, import_count=1,
    user_note=NULL, category=NULL

用户添加备注和分类：
  bill_transaction:
    id=100, user_note="公司聚餐", category="餐饮"

第二次导入相同数据（import_id=2）：
  bill_transaction:
    id=100, description="午餐", expense=50.00,  // 原始数据不变
    first_import_id=1, last_import_id=2, import_count=2,  // 更新追踪
    user_note="公司聚餐", category="餐饮"  // 用户修改保留！
  
  bill_transaction_import:
    {transaction_id=100, import_id=2, is_new=0}  // 新增关联
```

### 总结

- **交易核心数据**：保持首次导入的值
- **用户修改字段**：永久保留，不被覆盖
- **追踪字段**：更新为最新值
- **关联关系**：记录所有导入历史

  ├─ processExcelImport()  // Excel导入处理
  ├─ deduplicateTransaction() // 去重逻辑

### 4. Controller `controller/`

```java
- BillImportController.java
  ├─ POST /api/bill/import/csv    // CSV导入
  ├─ POST /api/bill/import/excel  // Excel导入
  ├─ GET  /api/bill/import/list   // 导入历史

  ├─ GET  /api/bill/transaction/list    // 交易列表

  ├─ DELETE /api/bill/transaction/{id}  // 删除交易
  └─ POST /api/bill/transaction/export  // 导出Excel
```

### 5. 核心导入逻辑

#### CSV导入流程

```java
1. 解析CSV文件 → CmbBillRecord列表
2. 创建BillImport记录（状态：PROCESSING）
3. 遍历每条记录：
   - 构建去重key（日期+时间+金额+描述）
   - 查询是否已存在
   - 如果存在：更新import_count，记录关联（is_new=0）
   - 如果不存在：插入新记录，记录关联（is_new=1）
4. 更新BillImport统计（new_count, duplicate_count）
5. 更新状态为SUCCESS
```

#### Excel导入流程

```java
1. 解析Excel文件 → BillTransaction列表
2. 创建BillImport记录
3. 遍历每条记录：
   - 去重检查
   - 如果存在：合并数据（保护user_note, category等用户字段）
   - 如果不存在：插入新记录
4. 更新统计和状态
```

## 🔧 数据迁移方案

### 1. localStorage → 数据库迁移工具

```javascript
// 前端迁移按钮
<el-button @click="migrateData">迁移历史数据到数据库</el-button>

// 迁移逻辑
1. 读取 localStorage 中的账单数据
2. 调用 POST /api/bill/migrate 接口
3. 后端批量插入到数据库
4. 迁移成功后清空 localStorage
```

### 2. 兼容性处理

```javascript
// 优先使用数据库，降级到 localStorage
if (数据库有数据) {
  从数据库加载
} else if (localStorage有数据) {
  提示用户迁移
  从localStorage加载
} else {
  空状态
}
```

## 📅 实施计划

### 工作量评估：5-7天

| 阶段 | 任务 | 工作量 |
|------|------|--------|
| 数据库 | 创建新表结构 | 0.5天 |
| 后端 | 实体类、Mapper、Service、Controller | 2.5天 |
| 前端 | 导入流程、列表展示、数据管理 | 2天 |
| 迁移 | localStorage迁移工具 | 1天 |
| 测试 | 功能测试、数据一致性验证 | 1天 |

### 渐进式升级策略

1. **第一阶段**：数据库和localStorage并存
2. **第二阶段**：引导用户迁移数据
3. **第三阶段**：完全切换到数据库

### 回滚方案

- 保留原有localStorage代码
- 通过配置开关控制使用哪种存储
- 数据库问题时可快速回退
